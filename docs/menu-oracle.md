# Independent menu LCD references

`tools/capture-pc-menu-oracle.py` captures optional test references by executing
the pinned, locally assembled original ROM in PyBoy 2.8.1. This is an isolated
QA tool, not a content-pack builder, audio exporter, or game dependency. The
ROM, symbols, reference PNGs, traces, and provenance stay outside this repository.

The tool requires the completed external source workspace described in
[the content guide](game-content.md), including `pokecrystal.gbc`,
`pokecrystal.sym`, and `constants/item_constants.asm`. It rejects any ROM whose
SHA1 differs from `f4cd194bdee0d04ca4eac29e09b8e4e9d818c133`, and refuses an
output directory inside the repository. It does not download or rebuild content.

These setup and capture commands were executed on macOS with Python 3.9:

```sh
python3 -m venv "$HOME/.local/share/geothite/menu-oracle-venv"
"$HOME/.local/share/geothite/menu-oracle-venv/bin/python" -m pip install \
  pyboy==2.8.1 pillow==11.3.0
"$HOME/.local/share/geothite/menu-oracle-venv/bin/python" \
  tools/capture-pc-menu-oracle.py \
  --vendor "$HOME/.local/share/geothite/export-workspace/vendor/pokecrystal" \
  --output "$HOME/.local/share/geothite/menu-oracle-fixtures"
```

PyBoy uses its [null window mode](https://docs.pyboy.dk/api/pyboy.html), with
sound emulation disabled and no emulator save writes. The fixture initializes
item/mail RAM and a CPU call boundary. Original ROM routines then load fonts,
palettes and screen data, clear sprites, and draw the menus. Subsequent ordinary
joypad inputs exercise scrolling, item switching, quantities, and Mailbox
submenus. No Geothite renderer, rendered menu pixels, tilemaps, or palette pixels
are supplied to the emulator. This proves isolated menu rendering and source
cursor behavior; it does not prove a continuous playthrough to the PC.

The corpus contains 38 PNGs: one initial item list, eight item-move frames,
four withdrawal quantities, four deposit quantities, twelve deposit-scroll
frames, and nine Mailbox list/action/confirmation frames. JSON traces record
source cursor/scroll/switch or quantity values. Deposit scrolling presses Down
eight times and Up three times, including Cancel clamping and the final
index-three/scroll-two position required by the existing reentry regression.
`menu-oracle-provenance.json` records the ROM, source revision, symbol table,
item constants, generator hash, emulator version and capture method.

The selected tests read these files at runtime:

```sh
export GEOTHITE_ORACLE_FIXTURES="$HOME/.local/share/geothite/menu-oracle-fixtures"
export CRYSTAL_RENDER_TEST_PACK="$PWD/content-packs/core-modular.crystalpack"
export POKEGEAR_PC_RENDER_DIR="$PWD/target/menu-oracle-review"
cargo test --locked -p crystal-bevy pc_item_ -- --include-ignored
cargo test --locked -p crystal-bevy pc_deposit_ -- --include-ignored
cargo test --locked -p crystal-bevy pc_withdraw_quantity_matches_real_source_menu_frames
cargo test --locked -p crystal-bevy mailbox_windows_match_original_rom_lcd
```

Those are the standard Cargo entry points. The 2026-10-19 verification used a
privately compiled current-source test executable against the completed shared
dependency graph, with the same four filters: 23 + 6 + 1 + 1 tests passed.
Production CPU LCD captures and logs are under the ignored
`target/kanto-resume/menu-oracle-review/` and `menu-oracle-build/` directories.
All 38 source/production pairs were visually inspected. A separate whole-image
comparison found zero differing RGB5 pixels at every pixel of the production
4× expansion, including the initial list whose test asserts only source ink.
Regenerating the corpus twice produced identical PNG hashes.

These isolated LCD comparisons complement the production-controller clinic
service regressions and native room captures. They do not certify the complete
library suite, every PC surface, or all room art. The optional naming family described below supplies a separate corpus. Other
independent oracle families are not generated by this tool. Radio fixtures separately use
`CRYSTAL_ORACLE_FIXTURE_ROOT`; this tool's tests use `GEOTHITE_ORACLE_FIXTURES`.

## Nickname screens

The same pinned emulator can execute the original `NamingScreen` routine for
male/female Cyndaquil and genderless Magnemite. This command was executed:

```sh
"$HOME/.local/share/geothite/menu-oracle-venv/bin/python" \
  tools/capture-pc-menu-oracle.py \
  --vendor "$HOME/.local/share/geothite/export-workspace/vendor/pokecrystal" \
  --output "$HOME/.local/share/geothite/naming-oracle-fixtures" \
  --family naming
```

The initial fixture supplies species, party slot and DVs; the original routine
loads and draws the font, diploma palette, species heading, gender, icon,
cursor and empty name. Ordinary A/Right/A/B/Select/A/Start inputs then exercise
entry, movement, deletion, lowercase and END selection. No emulator pixels or
screen data are supplied. The output remains external: 32 idle frames and eight
editing frames per case, 120 PNGs total, plus traces and provenance. A second
generation reproduced every PNG hash. All 38 existing PC/Mailbox PNG hashes
also remain unchanged with the extended generator.

The comparison uses `GEOTHITE_ORACLE_FIXTURES` pointing at this naming directory
and the ignored `name_rater_nickname_pixels_match_original_rom_gender_icons_and_editing`
regression. It compares every LCD pixel in RGB5 against the available source
icon/cursor phases, without masking sprite regions. This proves the sampled
visible states, rather than synchronization of the original initial-entry
clock or every joypad subframe. `NAME_RATER_PIXEL_REVIEW_DIR` optionally saves
the actual production CPU compositions for inspection. Run the test with the
external pack supplied and `--include-ignored`. The native service-entry and
idle retained-LCD checks complement these isolated pixel comparisons.
