## Native art for outdoor rock stairs

Inspected actual37a09 collision and `renders/gyms/source-cave-indoor.png`. Authentic cave stair blocks are **12** `[FLOOR,FLOOR,WALL,FLOOR]`, **30** `[FLOOR,FLOOR,FLOOR,WALL]`, **36** `[FLOOR,WALL,FLOOR,WALL]` (TL,TR,BL,BR). These provide real stone stair pixels with ordinary walkable quadrants; align rock walls to the blocked quadrants, and join both stair ends to appropriate terrace floors. A stair should be a legible narrow ascent in a continuous rock face, not an isolated glyph on open lawn. Test both directions and lateral wall rejection at core resolution.

Do not substitute collision token STAIRCASE because it sounds suitable: `crystal-core/src/world/collision.rs:79` defines0x7a; `world/session.rs:1635` forces Down for it, as for CAVE/DOOR. LADDER0x72 is different: original Johto06 bridges use it without a warp and existing R11 ordinary walking checks include it. Cave07/14/1b include actual LADDER quadrants and are visually ladder/mouth blocks, not the stone stair choice above. No exterior stair warp event should be created unless an actual cave entrance is intended.

`north_shore_art.rs` currently copies only cave2c waterfall into appended block80, using one verified-unreferenced Johto glyph20. Three multiglyph stair blocks cannot reuse that one-slot recipe. Implement a bounded Rust native-art extension with checked unused destination glyph slots, exact cave2bpp/palette-bank data and preserved original quadrants, append explicit block IDs81+ without changing original00–80, and derive any behavior replacement aliases from the correct source. Assert original Johto files and original North Shore glyphs/collisions/palette values are unchanged. Validate bank-bit addressing and capacity before publication; fail instead of overwriting a referenced glyph. Source render must resolve the same recipe and native pixels. No generated replacement art or Python pack export.
